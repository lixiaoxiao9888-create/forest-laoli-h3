# 交付与投喂包（平台无关）

> 本文件解决一件事：**写完的稿子怎么变成一份不挑平台的投喂包，交出去就能跑。**
> 跑片、排队、并发、账号容量属于**你所用渲染端**的职责，本包不介入、不假定、不写死任何客户端。

---

## 一、交付三件套（投喂前必须齐）

| 件 | 内容 | 谁用 |
|---|---|---|
| `段NN_时长_标题.txt` | **剥壳后的六段式纯文本**（字段名独立一行 + 空行 + 内容，不带 `**`、不带 ``` 围栏） | 直接粘提示词框 / 走 API `prompt` 字段 |
| `图槽表.md` | Picture 1…9 → 文件名 + 各自锁什么（人物/场景/道具） | 挂图时照表挂 |
| `清单.json` | 每段的 name / file / duration / aspect / images[] | 你自己的渲染端脚本读，或人工照单投 |

**剥壳是硬要求**：H3 会把提示词原样编码，`**subject_definitions**` 这种 Markdown 标记会变成正文的一部分，模型真的会去画它。

---

## 二、剥壳硬规矩

1. 字段名单独一行，**不带** `**` `#` `-` ``` 等任何 Markdown 标记；
2. 字段之间空一行，字段内部**不要**人为折行（折行不影响，但别加缩进）；
3. `<d>` / `<Picture N>` / `<Subject N>` 等标签**原样保留**，不要被编辑器转义成 `&lt;`；
4. 台词里的中文标点保留，正文标点用英文；
5. 存 **UTF-8 无 BOM**（最好）。带 BOM 会在首个字段前插不可见字符，字段名解析可能失效——
   `h3_lint.py` v2.0.2 起会自动剥掉 BOM 容错，但**渲染端不一定容错**，交付前还是存无 BOM 干净。

---

## 三、图槽铁律（防省图错位 / 防贴错素材）

> **真机血泪教训**：很多"卡死""莫名多一个人""换了间屋子"其实是**省图导致槽位前移**或**人景贴反**，跟模型无关。

1. **`Picture N` = `images` 数组的第 N 张图（从 1 开始），不是资产名字里的数字。**
2. **全片槽位一次钉死，中间不用的图也必须挂上（严禁省图）**：
   - 反例：全片 `Picture 1 = 男主`、`Picture 2 = 老周`、`Picture 3 = 门厅`。到了第 2 段老周没出场，为"省额度"只传 `[男主.png, 门厅.png]`：
     - `门厅.png` 变成 `Picture 2`；
     - 正文里的 `Picture 3` 指向**空槽越界**。渲染端要么卡死，要么把门厅当人画。
   - 正解：**全片所有段的 `images` 数组保持相同长度与顺序**；某段不用老周，正文不提 `<Subject 2>` 即可，但 `images[1]` 依然放老周那张图占住 2 号槽。
3. **自检两条（本包能查的就在这里）**：
   - 正文里最大的 `Picture M` ≤ `images.length`（**越界 = 机检 `H36`**）：
     ```bash
     # 直接喂清单.json（§四 格式）：自动读同目录的 .txt、取 aspect、逐段查 H36 越界
     python scripts/h3_lint.py 清单.json --json
     ```
     只喂剥壳 `.txt` 时没有 `images` 数组，`H36` 不触发，必须人眼核；
   - `subject_definitions` 里"人物/Picture 1"的对应关系与 `images[0]` 的实际文件一致（人景贴反 → 出片直接换脸/人变房子）。
4. **文件名只认槽位号**：`素材库/人物/{槽位}_{名称}.png`，槽位号必须与 `<Picture N>` 完全一致。命名错了整段白跑。

## 四、清单 JSON 格式（通用，不绑任何客户端字段）

```json
[
  {
    "name": "段01_15s_规矩",
    "file": "段01_15s_规矩.txt",
    "duration": 15,
    "aspect": "9:16",
    "resolution": "720P",
    "images": [
      "1_pic1_林昭.png",
      "2_pic2_老周.png",
      "3_pic3_出租屋门厅.png"
    ]
  }
]
```

| 字段 | 说明 |
|---|---|
| `name` | 段名，与稿子标题一致 |
| `file` | 剥壳后的 `.txt` 文件名 |
| `duration` | 整数秒，取 4/5/8/10/12/15，**必须与稿内切点自洽** |
| `aspect` | **`9:16`（推荐）或 `16:9`（实测可用）**，全片一致，禁 `auto` |
| `resolution` | 按你的渲染端能力填，短剧验收线一般 720P 起，需要 2K 走二次放大 |
| `images` | **顺序 = 图槽顺序**，第 1 个元素就是 `Picture 1`，长度全片一致 |

> 有些渲染端用 `aspect_ratio` + `short_edge`（见 `h3-format.md §六` 路径 B），有些用 `ratio`（路径 A）。**字段名跟着渲染端走，值始终是 `9:16` 或 `16:9`，不写 `auto`。**

## 五、出片之后：三关复检

```bash
# 1. 规格核对（画幅是不是你要的那个、时长对不对）
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate \
        -show_entries format=duration -of default=nw=1 段01.mp4

# 2. 抽帧联络表（每秒一格，人眼查：门有没有提前开、有没有分身克隆人、有没有冻帧）
ffmpeg -y -i 段01.mp4 -vf "fps=1,scale=360:-1,tile=5x3" -frames:v 1 段01_联络表.jpg

# 3. 切点核对（切点数应与稿内 [Shot N] 数量吻合，多出来的切点通常是模型自己加的）
ffmpeg -v error -i 段01.mp4 -vf "scdet=t=6,metadata=print:file=-" -f null - 2>&1 | grep -o 'lavfi.scd.time=[0-9.]*'
```

**三关都过再进下一段**。跨段连续的项目，先跑段 01、验完末帧，再跑段 02——一次投十段再回头改，返工成本是十倍。

## 六、边界（明确不管的事）

| 事项 | 归谁 |
|---|---|
| 稿子能不能画出来、会不会崩 | **本包**（H1–H36 机检 + D01–D50 诊改） |
| 投喂包格式、图槽顺序、剥壳 | **本包**（本文件） |
| 排队、并发、账号通道、任务卡死重启 | 你的渲染端 |
| 出图（三视图/场景图）用哪个工作流 | 你的出图工具（`asset-layer.md` 只给提示词模板与版式） |
| 成片剪辑、字幕、配乐成片化 | 不在本包内 |
